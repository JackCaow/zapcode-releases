# zapAgent 1.14.5 — macOS Apple Silicon

Fewer approval prompts, and `git` works inside the sandbox.

- **Read-only commands no longer ask.** While commands run inside the OS sandbox, `pwd`, `ls`, `cat`, `head`, `tail`, `grep`, `rg`, `find`, `echo`, `which`, `date`, `uname`, `whoami`, `id` and read-only git (`status`, `diff`, `log`, `show`, `blame`, `ls-files`, `grep`, and the listing forms of `branch`, `tag`, `remote`, `stash`) run without a prompt. A task that used to ask about ten times now asks only for commands that write. The allowance is list-based: only the exact flags on the list are accepted, anything with shell redirection, chaining, substitution or an unquoted glob still asks, and so does a command whose directory leaves the project. Your own deny and ask rules still win, and the allowance is off whenever the OS sandbox is.
- **`git` runs as the real binary inside the sandbox**, not through macOS's `xcrun` shim. `git blame`, `show` and networked read commands such as `clone` of a public repository and `ls-remote` no longer fail with an `xcrun` cache error. The xcrun cache itself stays unwritable.

Still asks (by design):
- `git commit`, `checkout`, `merge`, `stash`, `fetch` and `push` write `.git`, so they go through an approved run outside the sandbox. Making commits work inside the sandbox was evaluated and withdrawn: whatever lets a sandboxed `git commit` write `.git` also lets a sandboxed command plant a link that a later, unsandboxed git would follow.
- Writing a file, `cd`, and anything not on the list.

Known limits are tracked in #59. In short: the read-only parser was attacked in three independent reviews and tightened each time, but cannot be proven complete; sandbox network access is still unrestricted.

Install or update with Homebrew:

```sh
brew tap JackCaow/zapcode-releases https://github.com/JackCaow/zapcode-releases
brew update
brew upgrade jackcaow/zapcode-releases/zapagent
```

For first installation, replace `upgrade` with `install`. The commands `zapAgent`, `zap` and `zapcode` are supported. Stop active tasks and the VM daemon before upgrading.

Commands run under the host OS sandbox by default; the bundled VM is opt-in (`ZAPCODE_EXECUTION=vm`). This distribution covers macOS Apple Silicon only. No model, API key or user data is included. Command-line archives are not stapled; first-use ticket verification needs connectivity. Keep Gatekeeper and quarantine enabled.
