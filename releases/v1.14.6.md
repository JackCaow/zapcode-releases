# zapAgent 1.14.6 — macOS Apple Silicon

Far fewer interruptions: commands that stay inside the sandbox no longer ask, and the network is now filtered.

- **Commands inside the OS sandbox run without a prompt.** Before, only a short read-only list did; every other command (a script, `pip install`, `npm install`) asked each time. Now anything that runs inside the sandbox just runs. Still asked: a command that leaves the sandbox (always, per call), writing files with the file tools in default mode, and anything your own deny or ask rules cover. Set `autoAllowSandboxedCommands: false` to go back to the read-only list only.
- **Package managers work inside the sandbox.** Existing pip, uv, npm, pnpm, yarn, bun, cargo and go caches, plus `~/Library/Python` and `~/.local/lib`, stay writable, so installs no longer need an approved run outside the sandbox.
- **The sandbox network is an allowlist (macOS).** Commands can reach package registries, git hosts, toolchain downloads and common CDNs, and loopback; anything else gets `403` with a hint to add the host to `sandboxNetwork.allowedDomains`. Cloud metadata addresses are never reachable. Hostnames only, TLS is not inspected. Turn it off with `sandboxNetwork.mode: "open"` or `ZAPCODE_SANDBOX_NETWORK=open`. Linux and Windows still have open network inside the sandbox.
- **Fixed: multi-line commands that start with `cd <dir> &&` never ran.** Heredocs and `python3 - <<'PY'` scripts were dropped with a "success without using the process launcher" error, so the model had to retry. They run now.
- **Fixed: `/sessions` titled a session by a slash command.** A session now takes its title from the first real prompt; a session that only ran commands is not listed.

Known limits are tracked in #59: sandboxed commands can write the Python user directory and package caches (a later unsandboxed run could import what a sandboxed one planted), the network filter does not stop uploads to an allowed host, and Linux/Windows have no network filter yet. A hosted CI test (`TestDaemonComputerTaskSurvivesClientDisconnectAndReplaysCursor`) is flaky on Ubuntu (#66).

Install or update with Homebrew:

```sh
brew tap JackCaow/zapcode-releases https://github.com/JackCaow/zapcode-releases
brew update
brew upgrade jackcaow/zapcode-releases/zapagent
```

For first installation, replace `upgrade` with `install`. The commands `zapAgent`, `zap` and `zapcode` are supported. Stop active tasks and the VM daemon before upgrading.

Commands run under the host OS sandbox by default; the bundled VM is opt-in (`ZAPCODE_EXECUTION=vm`). This distribution covers macOS Apple Silicon only. No model, API key or user data is included. Command-line archives are not stapled; first-use ticket verification needs connectivity. Keep Gatekeeper and quarantine enabled.
